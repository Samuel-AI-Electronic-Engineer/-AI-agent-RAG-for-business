Frontend — capa de presentación

React 19 Activo

Biblioteca de interfaces de usuario basada en componentes. Permite construir UIs reactivas donde el estado controla la vista automáticamente. Usa el Virtual DOM para renderizar eficientemente solo lo que cambia.

Rol en el proyecto: Renderiza toda la interfaz — home, modales, cards de poemas, dashboard, formularios.

Vite 8 Activo

Bundler de nueva generación. Usa módulos ES nativos en desarrollo (sin empaquetar) y Rollup en producción. Arranque instantáneo y Hot Module Replacement en milisegundos.

Rol en el proyecto: Servidor de desarrollo, compilación optimizada para producción, gestión de assets.

React Router v7 Activo

Enrutador declarativo para React. Maneja la navegación entre páginas sin recargar el navegador (SPA). Define rutas protegidas, rutas anidadas y navegación programática.

Rutas activas: / → /login → /register → /dashboard → /poem/:id → /publicar

Zustand 5 Activo

Estado global minimalista. Gestiona el usuario autenticado y el token JWT a través de toda la app sin prop drilling.

TanStack Query 5 Activo

Caché inteligente de peticiones al servidor. Maneja loading, error, refetch automático y sincronización en segundo plano.

Axios 1.16 Activo

Cliente HTTP con interceptores. Inyecta el token JWT automáticamente en cada petición al backend.

Framer Motion 12 Activo

Animaciones declarativas y fluidas. Maneja transiciones de página, aparición de cards y efectos cosmos.

Backend — capa de lógica

FastAPI 0.115 Activo

Framework web Python asíncrono de alto rendimiento. Genera documentación OpenAPI automática (Swagger). Usa type hints para validación automática de datos con Pydantic.

Endpoints activos: /auth/login · /auth/register · /users/me · /posts (CRUD completo) · /posts/featured · /health

SQLAlchemy 2.0 Activo

ORM que mapea clases Python a tablas SQL. Gestiona relaciones, migraciones y consultas de forma segura contra SQL injection.

Pydantic 2.9 Activo

Validación de datos con tipos Python. Esquemas de entrada y salida de la API. Serialización y deserialización automática.

Passlib + Bcrypt Activo

Hash irreversible de contraseñas. Nunca se guarda texto plano en la base de datos.

Python-Jose (JWT) Activo

Generación y validación de tokens JWT firmados. Autenticación stateless entre frontend y backend.

Base de datos — capa de datos

PostgreSQL 17 Activo

Motor de base de datos relacional open source. Soporta ACID completo, índices avanzados, JSON nativo y consultas complejas. Tablas activas: users · posts

Patrones de arquitectura aplicados

REST API

Comunicación stateless entre frontend y backend mediante verbos HTTP (GET, POST, PUT, DELETE) y respuestas JSON estandarizadas.

JWT Stateless Auth

El servidor no guarda sesiones. El token firmado contiene toda la información del usuario y viaja en cada petición.

Arquitectura en capas

Routers → Schemas → Models → Database. Cada capa tiene una única responsabilidad y no salta a capas no adyacentes.

Component-driven UI

Cada pieza visual es un componente React reutilizable, aislado y con su propio estado. Composición sobre herencia.

ORM Pattern

SQLAlchemy abstrae el SQL. Los modelos Python representan tablas. Previene SQL injection y simplifica las consultas.

Global State (Zustand)

Estado del usuario centralizado. Un solo store accesible desde cualquier componente sin prop drilling.

Plan de despliegue a producción

Paso 1 — Repositorio Git Primero

Crea un repositorio en GitHub con dos carpetas: backend/ y frontend/. Asegúrate de que .env esté en .gitignore en ambos proyectos. Este es el punto de partida para todo el deploy.

Paso 2 — Base de datos en la nube Railway

En railway.app crea un servicio PostgreSQL gratuito. Copia la URL de conexión que te da Railway — tendrá este formato:
postgresql://user:pass@host:5432/dbname
Reemplaza tu DATABASE_URL en las variables de entorno del servidor.

Paso 3 — Backend en Railway FastAPI

En Railway crea un servicio web desde tu repositorio GitHub (carpeta backend/). Configura el comando de inicio:

uvicorn app.main:app --host 0.0.0.0 --port $PORT

Agrega las variables de entorno: DB_HOST, DB_PASSWORD, SECRET_KEY, DEBUG=False, ALLOWED_ORIGINS con la URL de Vercel.

Paso 4 — Frontend en Vercel React

En vercel.com importa el repositorio GitHub (carpeta frontend/). Vercel detecta Vite automáticamente. Agrega la variable de entorno:

VITE_API_URL=https://tu-backend.railway.app/api/v1

Actualiza src/config/api.js para leer esta variable con import.meta.env.VITE_API_URL.

Paso 5 — Dominio propio Opcional pero recomendado

Registra libretazul.com.co en NIC Colombia (~$35.000/año) o GoDaddy (~$50.000/año). Apunta el DNS a Vercel para el frontend y a Railway para la API. Ambas plataformas gestionan el certificado HTTPS automáticamente.
